# 踩坑与检查清单

## A. 已经踩过的坑（症状 → 原因 → 修法）

### A1. 新加的卡从来不出现在对局里

**症状**：卡录进去了，测试也过，但自动对战里从来没见过这张卡。
**原因**：`buildTestDeck` 早期写法是「每张作者卡 3 份，然后 `slice(0, size)`」。
17 张卡 ×3 = 51 张 > 30，排在后面的卡被整张切掉。
**修法**：先算份数再逐轮发牌。

```js
const copies = Math.max(1, Math.min(3, Math.floor(size / USER_CARDS.length)));
for (let c = 0; c < copies; c++) for (const card of USER_CARDS) deck.push(card.id);
```

已加回归测试「卡组构建不会漏掉任何一张作者卡」。**加完一批卡后顺手确认这条测试还在跑。**

---

### A2. 卡在手里永远灰着，点了没反应

**症状**：某张锦囊 `isPlayable` 返回 false，手牌置灰。
**原因**：`analyzeSpell` 只认识「需要点选」的选择器。
「自己的国王」「敌方所有单位」这类**不需要点选**的选择器产生不了目标列表，
于是被判定为「当前没有合法目标」。
**修法**：`app/js/main.js` 的 `NO_CHOICE_TARGET_KINDS` 白名单 + `needsChoice` 标志。
新增任何「引擎自己就能确定目标」的选择器，都必须登记进这个集合。

上一批的「紧急包扎」（`ownKing`）和「虫群」（`allEnemyUnits`）都踩过。

---

### A3. 界面高亮了一个目标，点下去却没生效

**症状**：能点，但打出去什么都没发生。
**原因**：`matchesTargetFilter` 有三处调用方（引擎 / 界面 / AI），
新增的 filter 条件或上下文只改了其中一处。
**修法**：三处统一传 `filterCtx(state)`。
引擎自己有最终校验，所以界面/AI 的 bug **不会**让非法目标生效 —— 表现为「静默失败」。

---

### A4. 光环来源死了，效果却还在

**症状**：拷问官被消灭了，敌方单位还是 -3 攻。
**原因**：光环被直接写进了 `unit.atk`，而「撤销」没有发生。
**修法**：光环一律走 `auras.js` + `effectiveAtk`，`unit.atk` 只存永久值。
**永远不要**为了省事在卡牌效果里直接改别的单位的 `atk` 来表示光环。

---

### A5. 界面显示的攻击力和实际打出的伤害对不上

**症状**：棋盘上写着 5 攻，打出来只有 2。
**原因**：漏了某处 `unit.atk` → `effectiveAtk`。
**修法**：grep `\.atk`，逐个确认。必查清单见
[引擎扩展指南.md](引擎扩展指南.md) 第 6.4 节。

---

### A6. 对局卡死 / 抛「触发链超过 1000 步」

**症状**：自动对战跑不完。
**原因**：触发式异能自己造成的伤害又触发了自己（或另一个同类异能）。
**修法**：`runTriggeredEffects` 里的 `noKeywordsForDamage` / `noWatchersForDamage` 护栏。
**并且必须写测试断言伤害次数是个确定的小数字** —— 只删掉护栏会静默地让伤害翻倍，
比崩溃更难发现。

---

### A7. 同一张卡要玩家点两次目标

**症状**：打「骨折」时要选两次敌人。
**原因**：两个数值拆成了两个 op，每个 op 各自解析一次目标。
**修法**：合成一个动作。用 `modifyStats`（一次拿到目标，同时改 atk 和 maxHp），
而不是 `buffAtk` + `debuffMaxHp`。

---

### A8. PowerShell 脚本报奇怪的语法错误 / 中文变乱码

**症状**：`tools/*.ps1` 突然解析失败，报错位置莫名其妙。
**原因**：Windows PowerShell 5.1 把**没有 BOM** 的 `.ps1` 当作 ANSI 读取，
UTF-8 的中文注释被拆成非法字节。
**修法**：`tools/*.ps1` 必须是 **UTF-8 with BOM**。
**每次用 `edit` / `write` 工具改过 `.ps1` 之后，都要重新写回 BOM**：

```powershell
$t = [System.IO.File]::ReadAllText($p)
[System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding $true))
```

（CSV 同理，用 BOM 的 UTF-8，否则 Excel 打开是乱码。）

---

### A9. 构建在原生命令的警告上失败

**症状**：`javac` 的 deprecation 提示让整个构建中止。
**原因**：`$ErrorActionPreference = 'Stop'` 会把**原生命令写进 stderr 的任何输出**
当成终止错误。
**修法**：改成 `'Continue'`，然后显式检查 `$LASTEXITCODE`。

---

### A10. CSV 列错位

**症状**：`Import-Csv` 出来的列对不上。
**原因**：效果文本里有**半角逗号**却没有加引号。
**修法**：含半角逗号的字段一律加双引号（中文全角逗号 `，` 不影响）。

---

### A11. 卡面文字重复、很吵

**症状**：单位牌上「狂热」出现两次（一次是词条标签，一次在效果文字里）。
**修法**：`text` 字段里**不要重复写词条名** —— 词条已经由 `keywords` 单独渲染成标签了。

---

### A12. `queueTrigger` 存 uid 而不是对象引用

**症状**：`被消灭:` 异能执行时报错或静默失效。
**原因**：单位被消灭后已经离开棋盘，按 uid 反查查不到。
**修法**：`queueTrigger` 存的是**单位对象的引用**。这一点不要改。

---

## A+ 前端部分的坑（做界面时才会遇到）

### A13. 顶层函数重名 → 静默覆盖 → 无限递归

**症状**：报 `Maximum call stack size exceeded`，但栈顶在 `rng.js` 里，完全看不出跟界面有关。
**原因**：`tools/build-web.mjs` 把所有模块**拼进同一个 IIFE 作用域**。
`app/js/main.js` 里定义了 `function startGame()`，而 `engine.js` **导出**了 `startGame` ——
重名之后命名空间对象 `G.startGame` 也被指向了界面函数，
于是 `newGame → G.startGame → newGame → …` 无限递归。
**修法**：改名（`startGame` → `startNewGame`）。
**加固**：`build-web.mjs` 现在会扫描所有模块的顶层声明，
重名**直接构建失败**并列出是哪两个文件。别再靠运气。

### A14. 编辑工具会悄悄去掉 .ps1 的 BOM

**症状**：`tools/*.ps1` 突然报 `Unexpected token '}'`，报错行显示 `Write-Host '鈹€' * 58`。
**原因**：`edit` / `write` 工具保存时去掉了 UTF-8 BOM，PowerShell 5.1 按 ANSI 读，中文全乱。
**修法**：`node tools/build-web.mjs` 现在会**自动把所有 `tools/*.ps1` 补回 BOM** 并提示。
如果手工改过 .ps1，跑一次打包再构建 APK。

### A15. WebView 里 `alert` / `confirm` / `prompt` 不工作

**症状**：点「删除」没反应；确认框永远不出现。
**原因**：`MainActivity` 用的是裸 `WebChromeClient`，没有实现 `onJsAlert/onJsConfirm/onJsPrompt`，
默认实现直接返回 `false` —— 弹窗被静默吞掉，`confirm()` 永远返回 false。
**修法**：删除确认这类交互**一律在页面内做**（本项目用的是「点一次变成『确认删除』，再点一次才删」）。
要么就别用浏览器原生弹窗。

### A16. 新增一个网页资源要改三个地方，漏一个就是设备上白屏

**症状**：本地打开好好的，装到手机上样式没了 / 白屏。
**原因**：`app/<file>` 需要同时出现在
① `app/index.html` 的引用、② `tools/build-apk.ps1` 的 assets 拷贝清单、③ `app/_preview.html`（否则截图会骗你）。
`app/screens.css` 就漏了 ①②，本地截图因为 `_preview.html` 也没引用所以「看起来正常」。
**修法**：现在 `verify-apk.ps1` 会
① 遍历 APK 里**每一个** assets 条目反向比对源文件，
② 解析 `index.html` 的 `href`/`src`，断言每个本地引用都在包里。
加了新文件就跑一次 `verify-apk.ps1`。

### A17. 改了 CSS 却没改预览页 → 截图验证是假的

**症状**：截图看着没问题，真机上一塌糊涂。
**原因**：`_preview.html` 只链接了一部分样式表，而 `index.html` 链接了全部。
**修法**：`_preview.html` 的 `<link>` 必须和 `index.html` 保持一致。
**改界面后一定要同时看 `_preview.html` 和 `index.html` 两条路径。**

### A18. d8 遇到带 `this$0` 的类就崩

**症状**：
```
=== [6] d8 生成 classes.dex ===
Error in ...\NativeBridge$1.class:
java.lang.NullPointerException: Cannot invoke "String.length()" because "<parameter1>" is null
Compilation failed with an internal error.
```
**根因（已用最小复现坐实）**：build-tools 34.0.0 自带的 **R8 8.2.2-dev 在写 dex 阶段，
只要遇到带合成字段 `this$0`（外层实例引用）的 class 就内部 NPE**。

| 被测类 | 字段 | d8 |
|---|---|---|
| 静态方法里的匿名类，**不捕获**外层 | 无 | OK |
| 静态方法里的匿名类，捕获局部变量 | `val$target` | OK |
| 实例方法里的匿名类 | **`this$0`** | **崩** |
| **具名非静态内部类** | **`this$0`** | **崩** |
| 具名 **static** 嵌套类 | 无 | OK |

**所以触发条件只看有没有 `this$0`，和「匿名 / 具名」无关，和文件名有没有 `$` 也无关。**

**修法**：Java 侧不要写**非静态内部类**（含实例方法里的匿名类）。
需要捕获外层就通过**构造器参数**显式传进去，类写成**顶层类**或 **static 嵌套类**。
`new Runnable() {}` 写在实例方法里是最常见的踩法。
`--min-api 24`、`--release 8` 都救不了 —— 与触发条件无关。

**验证**：`Get-ChildItem android\build\classes -Recurse -Filter '*$*'` 应为 0 条。

### A19. 加了「屏幕守卫」之后游戏卡死，既出不了牌也结束不了回合

**症状**：**有时**开局后什么都不能做 —— 不是自己的阶段，AI 也不动。
**原因**：给 `tick()` 加了 `if (screen !== 'game') return;` 之后，
`startNewGame()` 仍然是「先调 `newGame()`（内部会调 `tick()`）→ 再设 `screen = 'game'`」。
于是 `tick()` 在守卫处直接返回，**整个回合循环根本没启动**。
「有时」是因为先手随机 —— 只有 AI 是先手时才暴露。
**修法**：**先切屏，再建局**。

```js
function startNewGame() {
  screen = 'game';   // ← 必须在 newGame() 之前
  newGame();         //   newGame() 内部会 tick()
  refresh();
}
```

**一般规律**：任何「初始化函数内部会启动循环/定时器」的地方，
它依赖的全局状态（屏幕、模式）都必须在调用它**之前**设好。
**回归测试**：`check-bundle.mjs` 里有一条专门反复开局直到碰到「AI 先手」，
再断言有计时器排队且阶段能推进 —— 不覆盖这个场景的测试抓不到它。

### A20. 提示文字排在手牌下面 = 玩家看不到

**症状**：选了一张锦囊，界面没有任何提示「该点哪里」。
**原因**：`view.hint` 渲染在手牌**之后**，390×844 的屏幕上直接被挤出可视区。
而且 `.hint` 在 CSS 里是 `position: fixed; bottom: 142px` 的浮动气泡，
一旦把它移进文档流就会和横幅/手牌挤在一起。
**修法**：把提示移到手牌**上方**，并在 `screens.css` 里把 fixed 定位改回 `static`。
**自检**：改完 UI 一定要截图看**实际视口**（用 `_frame.html`），别只看 DOM。

### A21. 按钮点得动、屏幕也切了，但就是「进不去」

**症状**：首页 →「开始游戏」→「AI 对决」→ 选难度 → **又回到二级菜单**。
玩家原话是「AI 对决进不去」。
**原因**：`handleAction` 里 `set-difficulty` 分支写的是 `screen = 'play'`，
而 `choose-ai` 永远跳难度页 —— 于是这是一个死循环：
**整条路径上没有任何一个按钮会调 `startNewGame()`**。
**修法**：难度行只负责「选中」（留在难度页），另加一个明确的
「开始对战」按钮（`data-act="start-ai"`）负责开局。
**一般规律**：**多级菜单的每一级都要有一个「真的开始」的出口**。
一级菜单里能进去、却出不来（或出不到对局）的路径，光看代码很难发现。
**为什么测试没抓到**：`__go('play')` 这种钩子**直接改 `screen`，绕过路由表**。
所以门禁里必须有 `__nav(act, dataset)` 这种「走真实 `handleAction`」的断言，
只测 `__go` 等于没测导航。

### A22. 冷启动点「回放」没反应（不是没渲染，是 refresh() 抛异常了）

**症状**：刚打开 App（这一节还没打过任何一局）→ 点「回放对局」→ 点某局的「回放」，
**什么都没发生**，界面还停在列表上。
**原因**：`refresh()` 的回放分支里调了 `computePlayable()`，
而那个函数读的是**实时对局**的 `state`，回放渲染的却是 `replayCtx.player.state`。
冷启动时 `state === null` → `TypeError` → `refresh()` 中断在中间，
于是 `stage` 上留着的还是上一屏的 HTML。
`screen` 其实已经变成 `'replay'` 了，所以「看状态一切正常，看界面什么都没有」。
**修法**：回放是**只读**的，单独拼一份 `replayView`
（合法落点/可出牌/选中项全部清空），**不要**去碰实时对局的任何状态；
同时给 `computePlayable()` 加 `if (!state) return;` 兜底。
**自检**：门禁里有一条 `__dropLiveGame()` → `__go('replays')` → 点回放 →
断言「渲染体积 > 1200 字节且出现控制条」。
**一般规律**：只要一个渲染分支会去读**另一个对局**的状态，就一定会出这种事。

### A23. 场上卡牌看不出它干什么

**症状**：棋盘格子只有名字 + 词条 + `⚔N ♥N`，**卡面文字完全看不到**；
点场上单位也没反应 —— 判不出这张牌在场上的效果。
**原因**：`handleUnitClick` 开头就是 `if (view.selectedIid === null) return;`，
也就是「手上没选牌时点单位 = 什么都不做」。格子太小，塞不下卡面文字。
**修法**：手上没选牌时点单位 → 弹出详情面板
（`view.infoUid` → `unitInfoHTML`）：有效攻击力与光环修正、生命、
**词条全文**（`KEYWORD_DEFS[k].note`）、`def.text` 卡面效果、开战打向谁。
开局给一句 `view.hint = '点场上的卡牌可以查看它的效果'` 做引导。
**注意**：面板的遮罩才挂 `data-act="close-info"`，面板本体不挂 ——
否则拖动看长文本会把它关掉。

### A24. 版本号有三处，漏一处就会装出「名字是新的、内容是旧的」

**症状**：`dist` 里生成了 `ka-pai-0.5.2.apk`，装到手机上 `versionName` 还是 0.5.1，
而且**覆盖安装失败**（versionCode 没涨）。
**原因**：`aapt2 link --version-code/--version-name` **只在 manifest 没写这两个属性时才生效**，
manifest 里写了就以 manifest 为准。三处要同步：
`tools/build-apk.ps1` 的参数、`android/app/AndroidManifest.xml`、
`app/js/screens.js` 的 `APP_VERSION`（设置页显示用）。
**修法**：`build-apk.ps1` 的 `[0]` 步直接读 manifest 和 `screens.js`，对不上就 `Die`。
**连带坑**：`tools/verify-apk.ps1` 里曾经把 APK 路径写死成 `ka-pai-0.5.1.apk`，
出了新版本之后它**还在验旧包**，一路 PASS，什么也没拦住。
现在默认取 `dist` 里最新的那个，并在有多个时给出警告。

**另一个连带坑**：`Get-ProbeTitle` 里写 `$x = & chrome ... --dump-dom $url 2>$null`
拿到的是**空字符串**（Chrome 的 stdout 在「赋值 + 重定向」组合下会丢），
三条断言全部静默失败，看起来像页面坏了。必须写
`(& chrome ... 2>&1 | Out-String)`。
同理，`"$base?demo=nav"` 里的 `?` 是**合法变量名字符**，
PowerShell 会解析成变量 `$base?demo`（空串），URL 退化成 `=nav`，
Chrome 直接去搜索 —— 要写 `"${base}?demo=nav"`。
