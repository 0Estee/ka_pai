## 二、P0 —— 会丢用户数据

### P0-1 按返回键直接退出 App，整局蒸发

证据：

- `android/app/java/com/kaipai/prototype/MainActivity.java` 没有 `onBackPressed()`；整个 `android/` 目录 grep 不到
  `onBackPressed` / `onKeyDown` / `dispatchKeyEvent` / `moveTaskToBack`。
  安卓默认行为就是 `finish()`。
- `app/js/store.js` 只持久化四样：`kapai.profile.v1`、`kapai.cloud.v1`、
  `kapai.replays.v1`、`kapai.settings.v1`（`store.js:309` 的 `SETTINGS_KEY` 附近）。
  **对局状态完全没有存档。**
- `MainActivity` 也没有 `onSaveInstanceState` / `onRestoreInstanceState`；
  进程被系统回收后重新 `web.loadUrl("file:///android_asset/index.html")`（`MainActivity.java:82`），一样回首页。
- 首页只有 `start-game` / `start-forge` / `open-replays` 三个入口（`app/js/screens.js` 的 `homeHTML`），
  **没有「继续对局」**。

后果：打到第 8 回合手滑按返回键 → 这局不存在了，金币、战绩、回放全无。

### P0-2 对局中没有任何「无损退出」

对局内菜单（`app/js/render.js:377-391`）只有两个按钮：

```
[重新开局]  [认输]
```

- `重新开局`（`app/js/play-input.js:1185`）**没有二次确认**，点了立刻 `startNewGame()`，旧局直接没了。
- `认输`（`app/js/play-input.js:1256`）走 `doAction({k:'s'})` → 引擎 `surrender()`
  （`engine/src/turns.js:319`），会正常结算，**算你输一局**，扣战绩。

玩家想「先歇一下、等下接着打」，唯一路径是认输或杀进程。

## 三、P1 —— 手感缺失

### P1-1 全应用零触感、零音效

- `grep -rn "navigator.vibrate|AudioContext|new Audio|howler|\.play()"` 在 `app/` 和
  `android/app/java/` 下**零命中**。
- `app/` + `android/` 下找不到任何 `.mp3/.ogg/.wav/.m4a/.aac` 文件。
- `WebSettings` 里没有任何振动相关设置（`MainActivity.java:53-65`）。

动画已经改过（0.74.0 工作区里的 9 个 keyframe），但触感这一层完全是空的 ——
牌打到对面脸上，只有视觉，没有那一下震动。这是"手感轻飘飘"的另一半。

### P1-2 全局没有错误兜底

- `app/index.html` 里没有 `window.onerror`。
- `app/js/*.js` 里没有 `unhandledrejection`（全仓库 grep 只命中 `ws.onerror`，那是连接状态）。
- `refresh()`（`app/js/render.js`）是整块重写 `#stage.innerHTML`。

任何一处字段 `undefined` 抛异常，画面就停在半截，玩家没有任何提示，只能杀进程 ——
而杀进程又撞上 P0-1。

## 四、P2 —— 可访问性

### P2-1 交互元素没有语义，屏幕阅读器用不了

- 全仓库 `aria-` / `role=` / `tabindex` 只有 12 处，且**全部在装饰性元素上**：

  `screens.js:488,507`（`aria-label` 容器）、`ui.js:63-64`（状态图标）。
- 真正要点的东西都是裸 `div` + click 委托：
  - 手牌 `app/js/ui.js:513` → `<div class="card" data-iid>`
  - 棋盘格 `app/js/ui.js:775` → `<div class="slot ...">`
  - 结束阶段按钮
- `MainActivity.java` 的 `s.setTextZoom(100)` **故意**忽略系统字号（防布局撑坏）。
  这个取舍本身合理，但意味着系统大字号用户没有替代方案。

## 六、性能（实测，知情项，不算缺陷）

`impossible` 难度 AI 规划是**主线程同步执行**：

| 场景 | p50 | p90 | 最大 |
|---|---|---|---|
| 中局常规（Node，29 次采样，6 个种子） | 67ms | 166ms | 716ms |
| 极端局面（22 张手牌 / 27 个合法出牌） | — | — | **1256ms** |

配置上限 `planBudgetMs: 6000`（`app/js/ai.js:188`），但那是**一整个回合**的总预算，
且 `aiTakeTurn` 一回合最多出 8 张牌共用同一个 deadline，所以不会叠加成 6 秒。
实测最坏 1.2 秒。

这期间 UI 会冻住。好在 `app/js/game-flow.js:461` 先把 `busyText = 'AI 思考中…'` 刷出去了，
玩家知道在等 —— 只是那 1 秒里所有 CSS 动画会卡帧。

## 七、整改方案

### 第一批：P0（半天到一天，必须先做）

#### 1.1 接管返回键

`MainActivity` 加 `onBackPressed()`，不要 `finish()`，调 JS 钩子：

```java
@Override
public void onBackPressed() {
    if (web != null) {
        web.evaluateJavascript("window.__kapaiBack && window.__kapaiBack()", null);
    }
}
```

JS 侧按屏幕分层：
- 对局中 → 弹「继续 / 退出到首页（该局作废，不结算）」
- 二级页 → `goHome()`
- 首页 → 再按一次才退出（或 `moveTaskToBack(true)`，安卓惯例）

**这一条单独做完，「手滑丢一局」就基本消失了**，成本极低。

#### 1.2 对局存档

`game-flow.js` 每次 `tick()` 之后把状态序列化进新 key `kapai.game.v1`。

要存的最小集合：

```
state（引擎状态本身是纯数据，JSON.stringify 得动）
deck / factions / difficulty / seed / humanSide / recording
```

**注意**：`cardLib`（256 张）不要进存档，会爆配额；恢复时用 `TEST_CARD_LIB` 重新挂上。

配 `visibilitychange` → 存盘，覆盖切后台被系统杀的情况。
首页加「继续对局」按钮，读到存档就显示。

#### 1.3 「重新开局」二次确认

用已经在用的 `fx-pop` 弹层，别用 `window.confirm`（WebView 里样式不可控）。

### 第二批：P1 手感（一天）

#### 2.1 震动

在 `render.js` 的 `applyTransientFx()` 挂钩子，DOM 侧统一发：

| 事件 | 震动 |
|---|---|
| 我方单位受击 | `vibrate(12)` |
| 阵亡 | `vibrate([0, 18, 40, 18])` |
| 打死敌方国王 / 对局结束 | `vibrate([0, 30, 60, 30, 60, 60])` |
| 抽牌 / 落子 | `vibrate(6)` |

⚠ 两个坑：
1. 安卓 WebView **默认不支持** `navigator.vibrate` —— 必须在 `MainActivity` 里自己实现：
   给 `NativeBridge` 加 `@JavascriptInterface public void vibrate(String pattern)`，
   JS 侧 `KapaiNative.vibrate(...)` 优先、`navigator.vibrate` 兜底。
2. 设置页要加「震动」开关，别默认强开。

#### 2.2 音效

先做 5 个交互音：出牌、受击、阵亡、抽牌、胜负。
用 Web Audio 的 `OscillatorNode` 合成就够，**不加音频文件**，包体不涨。

关键：`AudioContext` 必须在**首次用户点击**时创建（安卓 WebView 自动播放策略），
在 `main.js` 的第一次 `pointerdown` 里初始化。同样加设置开关。

#### 2.3 全局错误兜底

`app/index.html` 在 `bundle.js` **之前**加：

```html
<script>
window.addEventListener('error', function (e) { window.__kapaiErr && window.__kapaiErr(e); });
window.addEventListener('unhandledrejection', function (e) { window.__kapaiErr && window.__kapaiErr(e); });
</script>
```

`__kapaiErr` 在 `main.js` 实现：`console.error` + 在 `#stage` 上盖一层
「出了点问题，点这里返回首页」的最小面板 + 保证 `#stage` 能被重绘。
**别做自动重启**，那会掩盖真正的问题。

### 第三批：P2 / P3（随手做）

- **3.1** `package.json` 版本改 0.74.0，并在 `publish-release.mjs` 里加断言：
  `package.json` version === `screens.js` `APP_VERSION` === Manifest `versionName`，对不上就中止发布。
- **3.2** README 三处按实测数字改。第 140 行建议改成
  「仅申请局域网联机所需的 4 个普通权限，游戏本身完全离线可玩」—— 更准确，也更好卖。
- **3.3** `.gitignore` 放开 `app/dist/`；或更省事：`check-bundle.mjs` 开头加一句
  「`app/dist` 比任何一个 `app/js/*.js` 旧就自动 rebuild」。
- **3.4** a11y：手牌和格子加 `role="button" tabindex="0"` + `aria-label`（卡名 + 费用 + 攻/血）。
  投入产出比一般，看要不要面向无障碍用户。
