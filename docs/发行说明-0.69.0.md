# 发行说明 0.69.0

> 这一版只加一件事：**管理员能改玩家的具体数据**。对局规则、卡牌、联机协议都没动。

## 在哪

账户页 →「用户管理」（仅管理员可见）。每个用户卡片上多了一颗「改数据」，
点开就在卡片里展开一块面板（不弹窗 —— 改之前得先看清这个人现在是什么样）。

## 能改什么

**数值**（七个格子，一眼看全）：

| 字段 | 范围 | 备注 |
|---|---|---|
| 金币 | 0~1000 | 客户端上限；写更多会被熔成星尘 |
| 星尘 | 0~500 | 客户端上限 |
| 表现分 | 0~1000 万 | 旁边顺手标出「换算成几级」（等级没有独立字段，只由表现分推算） |
| 对局 / 胜 / 负 / 平 | 0~100 万 | 战绩 |

**强化**：「清空强化」一键把这个人的强化 / 精通全清掉（按钮上直接写现在有几张牌有强化）。

**整份 JSON**：展开「高级：改整份 JSON」可以整份替换存档（客户端先解析，格式错就不发请求）。
想精确塞某个卡牌的强化等级时走这里。

## 改了之后会发生什么

- 改的是**云端存档**：版本号 +1，并记一条审计（谁、什么时候、改了谁、改了哪些字段）。
- 玩家那台设备上的本地存档不会被动。他下次同步会撞上「云端已更新」，
  在二选一里点「用云端」才会采纳 —— 这样管理员的改动不会被一台离线手机的旧进度盖回去。
- 每张卡片下面还能看到「最近的管理操作」，改错了能立刻看出刚才动了什么。

## 权限

- 只有 `role === 'admin'` 的账号能读别人的存档、能改、能看审计日志；
  这些接口在服务端逐条校验（不是靠界面藏按钮）。
- 响应里永远不含密码的 salt / hash。
- 普通玩家调这些接口一律 403；没登录一律 401。

## 实现要点（给下次改的人）

- 服务端 `cloudflare/src/users.js`：`ADMIN_NUMBER_LIMITS` 是那份白名单（改字段就改它）、
  `cleanForge` 与客户端 `store.normalizeProfile` 同一套口径、`appendAudit` 写 `meta:adminlog`。
- 客户端 `app/js/cloud.js`：`adminEditOpen / adminEditSave / adminEditSaveRaw / adminEditClearForge`。
- 保存前一定先把输入框的值 **setField 落进状态**再触发保存：保存一开始就会重绘，
  直接从 DOM 读会把刚敲的数冲回原值（`play-input.js` 里那段注释写明了原因）。
- `cloudLastRequest()` / `cloudRequests()` 是给门禁用的请求留痕，正常运行时只是多留一个对象。
