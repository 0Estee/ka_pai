# 公网联机部署（Cloudflare）

> 本文讲**怎么把游戏放到公网**、让两台设备用房间号连一局。
> 协议本身（消息格式、锁步规则）仍以 [联机协议.md](联机协议.md) 为准；
> 这里只多了一件事：**每个请求都要带 `room`**，服务端靠它路由到房间。

---

## 0. 为什么是 Durable Object

网上大多数「联机小游戏」用一台常驻服务器管所有房间。Cloudflare Workers 不是那种东西：
它按请求起实例、请求结束就回收，**没有可放的全局变量**。

房间需要的恰恰是「有状态」：

- `seq` 要单调递增、不能重不能漏（两个玩家各自按序号对齐操作）；
- 长轮询要**挂在半空中**等对手操作，有消息立刻推下去；
- 一方退出要**立刻叫醒**对家，而不是让对家等满 20 秒超时。

Durable Object 正好是「一个房间一个对象」：单线程串行处理、能挂起 await、
自带存储、闲置自动休眠。所以：

```
浏览器A ──┐
          ├─► ka-pai.<你的域名>  ──(按房间号)──►  Room 对象 K7QM2P
浏览器B ──┘
```

静态文件（index.html / bundle.js / 图片）走同一域名的 `ASSETS` 绑定，
所以**不需要另开一个静态托管**，也就没有跨域问题。

## 1. 目录

```
cloudflare/
  wrangler.toml      ← 部署配置（房间对象绑定 + 静态资源）
  src/room.js        ← Worker 入口 + Room 对象（服务端全部逻辑）
  assets/            ← 构建产物，由 tools/build-online.mjs 生成，不要手改
```

`cloudflare/assets/` 是**生成目录**，等价于 APK 里的 `android/build/assets`。

## 2. 构建

```bash
node tools/build-online.mjs
```

它把 `app/` 打成一个可部署的站点：

- `app/index.html` → `assets/index.html`（`dist/bundle.js` 换成 `bundle.js`）
- `app/style.css` / `app/screens.css` → `assets/`
- `app/dist/bundle.js` → `assets/bundle.js`
- `app/img/*` → `assets/img/`（卡图、阵营图、爪印）
- 额外写一份 `assets/_build.json`（版本号 + 模块数 + 时间）

> 跑之前记得先 `node tools/build-web.mjs`，否则 bundle 是旧的。

## 3. 部署

```bash
cd cloudflare
npx wrangler deploy
```

第一次部署会提示建 Durable Object 命名空间，`wrangler.toml` 里已经写好
`new_sqlite_classes = ["Room"]`，直接回车即可。

第 0 次部署会顺带注册默认域名，形如：

```
https://ka-pai.<你的子域>.workers.dev
```

**但这个地址在国内直连打不开**（DNS 投毒 + SNI 拦截），所以正式入口用的是
自有域名 `https://wangzuo.icu` —— 配置就写在 `wrangler.toml` 的
`[[routes]]` 里：

```toml
[[routes]]
pattern = "wangzuo.icu"
custom_domain = true
```

`custom_domain = true` 时 wrangler 会自己建 DNS 记录并签发证书，
**不要再去控制台重复加一条 CNAME**，否则会冲突。前提是这个域名已经加进
同一个 Cloudflare 账号（把 NS 指过来即可）。

> 想换域名：改 `pattern` 那一行、`npx wrangler deploy` 即可。
> 客户端是从 `location` 推导站点地址的，协议和路径都不用改
> （只有 APK 从 `file://` 加载时才读 `app/js/cloud.js` 里的 `CLOUD_BASE`，换域名要一起改）。
> 2026-10-31 起正式入口是**裸域** `wangzuo.icu`（原来绑的是 `www.wangzuo.icu`，
> 那条解析已经撤了）。想让 `www.` 也能打开，就在控制台加一条 Redirect Rule 把 `www.` 跳到裸域。

### 登录

`npx wrangler login` 会开浏览器走 OAuth。若那台机器没法开浏览器，
改用 API Token（控制台 → My Profile → API Tokens → Create Token，
模板选 **Edit Cloudflare Workers**），然后：

```bash
export CLOUDFLARE_API_TOKEN=xxxxx
```

## 4. 怎么玩

1. 双方各自打开 `https://你的域名/`；
2. 主界面 → 开始游戏 → **联机对决** → **创建房间**；
3. 页面上会给出一个 6 位房间号（例如 `K7QM2P`）和一条邀请链接；
4. 把**房间号**念给对方，或把**链接**发过去；
5. 对方打开链接（或在大厅输入房间号）→ 自动进入同一房间；
6. 主机点「开始对战」。

房号字母表去掉了 `0/O/1/I`，因为房间号是要**口头念**的。

## 5. 一次对局里发生了什么

两端**不传棋盘**，只传操作。引擎是确定性的（随机数全来自种子），
所以同一串操作在两边跑出来的局面必然一致。

```
主机  ── start(seed, deck) ──►  客人        （开局只同步种子）
主机  ── act {k:'p'...}    ──►  客人        （之后每一步只同步操作）
双方  ── hash（每 8 步）   ──►  对方        （对账，不一致立刻报错）
```

`hash` 是把回合/阶段/双方王血/手牌数/棋盘快照拼起来算的 FNV-1a 32 位摘要。
它一旦对不上，说明两边跑岔了，会直接把对局停下来报错 —— 这比「默默各玩各的」好。

## 6. 已知限制

| 限制 | 说明 |
| --- | --- |
| 同时只有一个对手 | 一个房间号对应一局；开新局换个房间号 |
| 房间不会永久保存 | 闲置两小时后房间对象休眠回收，重进同一个房间号等于重开 |
| 长轮询上限 25 秒 | 到点返回空，客户端立刻重连，不是断线 |
| 只做 WebSocket 推送 | 发送仍走 `POST /api/send`，这样发送路径和局域网版完全一致 |

## 7. 自检

部署前后都能用这两组脚本验证，不需要开浏览器：

```bash
node tools/check-online.mjs         # 服务端时序：seq / 唤醒 / 离开 / WebSocket
node tools/check-online-match.mjs   # 真打一局：两端状态每步必须一致
```

本地起服务用：

```bash
cd cloudflare && npx wrangler dev --port 8787
```

两个脚本默认都连 `http://127.0.0.1:8787`，可用 `KAPAI_BASE` 覆盖。

## 8. 云存档与账号（0.61.0）

### 8.1 部署时要多做一步 migration

`cloudflare/src/room.js` 仍然是入口，但现在同时导出两个 Durable Object：

- `Room`：房间（v1，原样保留）
- `Users`：云存档账号（v2，全站单实例 `global`）

`wrangler.toml` 里已经加好 `USERS` 绑定和 `[[migrations]] tag = "v2"`。
**不要删 v1**；部署顺序是：

```bash
cd cloudflare
npx wrangler deploy --dry-run   # 先看配置
npx wrangler deploy             # 应用 v2 migration
```

### 8.2 管理员与密钥

- 默认管理员：`123 / 1145145`（首次初始化自动创建，密码只存 PBKDF2 哈希）。
- **部署后立刻换掉**：
  ```bash
  npx wrangler secret put ADMIN_PASSWORD
  ```
- 建议同时配 `AUTH_SECRET`（不配则首次在 Users 的 DO 存储里自动生成并持久化）：
  ```bash
  npx wrangler secret put AUTH_SECRET
  ```
- 可选 `PBKDF2_ITERATIONS`（默认 100000）。如果 Workers 计划 CPU 限额较低、
  登录超时，可调到 30000~50000；不要低于 10000。
- 管理员账号名可用 `ADMIN_USERNAME` 覆盖；`123` 始终保留，不能被普通用户注册。

### 8.3 接口

| 路径 | 用途 |
| --- | --- |
| POST /api/auth/register | 注册并自动登录 |
| POST /api/auth/login | 登录 |
| GET /api/auth/me | 校验当前 token |
| POST /api/auth/password | 改密码（旧 token 全部失效） |
| GET /api/save | 读取云端档案 |
| PUT /api/save | 上传档案（带 baseVersion，冲突返回 409） |
| GET /api/admin/users | 管理员用户列表 |
| POST /api/admin/reset-password | 管理员重置密码 |
| POST /api/admin/delete | 管理员删号 |

客户端在 http(s) 页面用同源 `/api`；APK 从 `file://` 加载时用
`https://wangzuo.icu/api`（常量在 `app/js/cloud.js` 顶部）。
跨域请求需要 Worker 的 CORS 头，`Users` 已经处理 OPTIONS 预检。

### 8.4 本地测试

```bash
npm run test:cloud
```

覆盖注册 / 登录 / token 篡改 / 存档版本冲突 / 管理员列表 / 重置 / 删号 /
CORS / DO 重启后 token 仍有效。不依赖 wrangler，也不需要联网。

### 8.5 已知边界

- 只同步 **profile**（金币、等级、强化进度、战绩）；**回放不同步**。
- `Users` 是全局单实例，所有账号写操作串行；当前量级够用，用户量大后要按用户名分片。
- 没有邮箱 / 找回密码；忘记密码只能由管理员重置。
- 管理员口令默认值是用户指定的弱口令，仅用于首次进入；生产必须换。
