# 发行说明 · 0.64.0

> 这一版两件事：**把「不同网络下联机双方都出不了牌」修掉**，以及**按作者给的参考图，
> 把所有界面统一成同一套语法**。

---

## 1. 联机：跨网络开局后双方都出不了牌

### 结论先说

不是网络问题，是**开局顺序**的问题：

```
旧：applyStart()（本地开局 → 界面 → tick 排第一拍 260ms 后）→ 发 start → 对端收到 start
新：发 start（等到服务端确认）→ applyStart()（本地开局）
```

主机的第一拍自动阶段只有 260ms 的准备时间，而「发 start」要先等 `/api/start`
这一趟往返回来 —— 移动网络一趟 100~400ms，于是**第一条 `{k:'a'}` 抢在 `start`
前面到达对端**。对端那时还没有棋盘，那条操作被静默丢掉，两端步数从此永久差一截：

* 客人一直在「等待对手…」（它以为还没轮到主机推进）；
* 主机一直在等客人的操作（它以为已经推进过了）。

同一 Wi-Fi 下 RTT 只有几毫秒，抢跑窗口小到踩不中，所以以前只在局域网里"看着是好的"。

### 三处修改

| 位置 | 改动 |
|---|---|
| `Session.beginGame` | **先广播 start、再本地开局**；发送失败直接抛错，留在大厅重试（不再开一局"只有一边在跑"的棋） |
| `Session.handleMessage` | start 之前到达的操作**先攒进 `early`**，start 一到按原顺序补执行 |
| 每条 `act` 带序号 `n` | 收到 `n > step` 说明中间丢了包：发 `{t:'need', from}` 要，对端用 `{t:'give', list}` 原样回放补上（不用重建棋盘，也不用重开一局） |

另外两处会让"看起来像断线"的隐患一起收掉：

* **长轮询被自己的超时掐断**：轮询要挂 20 秒，而客户端所有请求共用一个 12 秒上限 ——
  于是每次空闲等待都必然 abort，状态在"已连接 / 重连中"之间来回跳，连续 60 秒就会
  走到"连接已断开"、会话直接停掉。现在轮询按自己的时长 + 8 秒余量算超时。
* **发送不再并行**：服务端的 seq 是按到达顺序分配的，两条 POST 同时在路上就可能换序。
  现在发送串成一条链，上一条落地才发下一条；界面不等广播（最多等 3 秒），所以不会再
  出现「点了一张牌，界面卡 3 秒才动」。

### 回归测试

`tools/checks/43-mp-lockstep.mjs`（进 `npm run check` 门禁）：

1. 开局时 **start 必须排在所有操作前面**；
2. start 之前抢跑到的操作**不能丢**，start 一到按序补执行；
3. 故意丢一条操作，靠 need / give 补齐后**两端指纹重新一致**。

## 2. 所有界面统一成「一张黑纸上的账本」

参考图（0.60.1 的首页）给出的语法只有五条，这一版把它落到每一屏：

1. 底是一张**近黑的纸**（`#0b0908`）—— 胡桃木、绒布、浮雕、外发光整块撤掉；
2. 一屏只有**一个实心块**：整宽反白胶囊的主按钮；
3. 标题与大数字用**衬线**，说明文字小一号无衬线；层级靠字号和留白，不靠框；
4. 分块只靠一条 **1px 头发丝线** + 留白；
5. 金只给"当下的那一行、货币数字、进度条"，不描边、不做渐变、不发光。

覆盖到的界面：首页、开始游戏、强化模式、AI 难度与阵营、联机入口、加入房间、
联机大厅、设置、云存档、用户管理、回放列表、回放播放、强化工坊，以及对局屏的
外框（顶栏 / 状态条 / 阶段条 / 棋盘格 / 手牌区）。

顺带修掉的：

* 首页徽记与装饰线（参考图里没有），标题从金色浮雕改回奶油衬线；
* 浅色 / 玻璃主题下主按钮会"消失"（被 0.62 那层的高特异性渐变盖住），现在钉死；
* 阵营行 / 难度行整排都亮成"已选中"，现在只有一行是金名；
* 联机页、云存档页那些"套了个框"的提示条，改成一行字 + 一条竖线。
