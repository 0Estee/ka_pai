# 0.34.0 发行说明

> 可直接覆盖安装 0.33.0（versionCode 34）。

## 修了什么

### 1. 每局打完不会生成回放（作者 2026-10 反馈）

根因是**回放存错了地方**。回放原先存在 WebView 的 localStorage 里，而 localStorage 是
**按来源隔离**的，App 里同时存在两个来源：

- 首页来自 `file:///android_asset/index.html`
- 联机页来自 `http://主机:8765`（客人导航过去的那一份页面）

于是：在联机页打完的那一局，回放存进了 http 那个来源，回到首页点「回放对局」自然是空的；
单人局反过来在联机页也看不到。另外 `file://` 来源在部分设备上根本拿不到 localStorage，
只能退化到内存存储，关掉页面或者重启 App 就什么都没了。

（玩家档案早就遇到过同一个问题，`app/js/store.js` 里也写明了必须走 SharedPreferences，
只有回放没跟上。）

修法：回放改走和玩家档案同一条原生存档通道。

- Java 侧 `android/app/java/com/kaipai/prototype/NativeBridge.java` 新增
  `readReplays()` / `writeReplays(json)`，与既有的 `readProfile` / `writeProfile`
  同样存进 `SharedPreferences("kapai_store")`；单份超过 150 万字符时直接返回 false，
  交给 JS 侧的「丢一半重试」处理。
- JS 侧 `app/js/store.js` 的 `loadReplays` / `saveReplays` / `replaysBytes` / `__resetAll`
  优先走这个通道；没有桥（桌面浏览器、旧版 APK）自动退回 localStorage 或内存，
  并会把旧版本留在 localStorage 里的那几局搬到原生存档里。

### 2. 顺带修：答完最后一问就打死国王时，那一局容易被漏掉

`app/js/play-input.js` 里「回答完把回合循环接回去」的守卫原来带着 `state.winner === null`，
于是「答完最后一道提问、同时把对面国王打死」这条路不会再调 `tick()`，
这一局的金币与回放只能指望别的定时器顺手触发，运气不好就丢了。守卫已去掉该条件，
统一走 `tick()` 里的终局分支结算。

## 门禁

新增 `tools/checks/07-replay.mjs` 一条检查「回放会写进原生存档通道（首页 file:// 与联机页 http:// 共用同一份）」：
装一个假的 `KapaiNative`，跑完一整局，断言写进原生通道的 JSON 是数组、条数比原来多 1、
内存里的列表同步更新。

这条检查确实抓得住：把 `app/js/store.js` 的 `replayStore()` 临时改成返回 `null`
（等价于旧版本没有这个通道），门禁立刻失败并给出
「有 KapaiNative 时回放没有走原生通道（还是塞进 localStorage 了）」。

- `node tools/check-bundle.mjs`：全绿
- `node engine/test/smoke.mjs`：86 个规则测试全过
