## 修好：存档里的回放，播到「选择」处出错

根因：把一局**打包进回放档案**时（`finishRecording`）漏掉了四个字段，其中 `choiceLog`（每一问的裁定流水）正是「选择」那块的关键：

- **少了 `choiceLog`**：回放播到需要抉择 / 点选时，每一问都落进「流水用尽」兜底  真人当时选的那一项被换成第一项，紧随其后的答案记录成了孤儿  报 `当前没有待处理的交互请求`，或者悄悄播错。
- 少了 `opening`：没有「发牌前一刻」的牌库 + rng，重建时只能照种子自己洗牌  抽牌顺序从第一步就歪。
- 少了 `shuffled`：重建时会把已经洗好的牌库**再洗一遍**。
- 少了 `humanSide`：联机时客人是 1 号，回放会错认成 0 号。

**为什么以前没发现**：内存里那份录制是完整的，只有「录完  存档案  再从档案播」这条路才暴露，而自检一直拿内存那份在验。

##  诚实说明（请你在手机上实测这条）

缺字段这个根因**已修**，并且加了门禁守住（存档里的回放必须带齐这四个字段）。

但「存档那条能否**逐步精确重演**」的自动验证，我**还没跑出绿灯**  我怀疑是那条检查自己按「动作条数」在档案里定位记录时撞车、选错了局（仓库里 `tools/checks/18-replay-choice.mjs` 的 TODO 里写了诊断步骤）。

所以请这样验：**打一局（中途做过「抉择」或点选目标） 看这局的回放  那一步应当如实重现**。若还是错的，把「哪一步、选了什么、回放里变成了什么」告我，我按 TODO 的第 1 步（打两边 `__stateBrief` 逐字段 diff）继续查。
