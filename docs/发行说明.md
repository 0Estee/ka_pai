## 怎么发（三种方式，挑一种）

###  网页点几下（最省事，不用给我任何凭据）
1. 打开 https://github.com/0Estee/ka_pai/releases/new
2. **Choose a tag**  选 `v0.28.0`（已推送，列表里会有）
3. 标题填 `0.28.0`，正文粘贴上面那段更新说明
4. 把 `E:\ka_pai\dist\ka-pai-0.28.0.apk` 拖到附件区
5. 勾不勾「pre-release」都行  **Publish release**

###  给我一个 fine-grained PAT（我全自动，以后每个版本都自动发）
- GitHub  Settings  Developer settings  Personal access tokens  **Fine-grained tokens**
- 只授权这一个仓库 `0Estee/ka_pai`，权限只要 **Contents: Read and write**
- 把 token 给我，我用 `git credential-manager` 存进 Windows 凭据管理器（**不写进 `.git/config`、不进仓库**）
- 之后我一条 API 调用就能建 Release 并上传 APK

###  全部版本一起发（作者 2026-10 要求） 推荐做法

**不要**给 13 个历史包各发一个 Release（它们对应不上任何 git 提交，tag 会指向 0.28.0 的代码 = 造假）。
正确做法：**发一个 Release，把 13 个 APK 全部作为附件挂上去**。GitHub 允许一个 Release 挂多个 asset，
这样 Releases 页面一次性给出所有可下载版本，而 tag 只有 `v0.28.0` 一个是诚实的。

Release 标题建议：`0.28.0（含历史版本 0.2.0~0.27.0）`，正文用上面的更新说明 + 这句：
> 附件里除 0.28.0 外，还挂着 0.2.0~0.27.0 的历史包  它们是 2026-10-02 之前逐个手打出来的，
> 早于本仓库的 git 历史，所以没有对应的 tag。
