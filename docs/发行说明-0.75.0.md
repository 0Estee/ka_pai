# 发行说明 0.75.0

## 改动

### 「不可能」开始自己回答引擎的反问（作者 2026-10-27）

引擎在效果结算中途会反问「选哪个」：弃哪张牌、封印谁、冰冻哪两条线、召唤落哪格、
抉择走哪一支、炼金拿哪张原料。AI 那一侧以前**没有答案**，全靠 `choices.js` 兜底
的「取第一个选项」—— 而选项按棋盘顺序排，等于随机。阵营超能力几乎全靠这些分支
生效，所以「用上阵营」在以前只是一句空话。

现在「不可能」会自己算这些答案（`app/js/ai.js` 的 `aiChoose`）。

**一个必须说清楚的结论：这一版没有把「不可能」变强。** 拿同种子配对、写死推演
档位 0 的对照量：

| 做法 | 打「困难」 | 打「噩梦」(+2费/+2牌/+8王血) |
|---|---|---|
| 不接管（0.74.0） | 90.0% | 70.0% |
| 接管全部提问（第一版实现） | 85.8% | 65.0% |
| **接管后放回引擎有内建策略的那两类** | **90.0%** | **70.0%** |

中间那行是负收益，来源很明确：`chooseEnemyTarget` 和一部分 `chooseUnit` 上，
引擎自己挂了 `request.choose = pickFragileTarget`（「能一刀杀就杀，否则打国王」），
是作者按这套卡池调过的口径。用「威胁值最大」去覆盖它是明确的亏。
逐类消融实测：

| 只接管 | 打「困难」 | 打「噩梦」 |
|---|---|---|
| 那两个有内建策略的 | 84.2% | 66.7% |
| 其余五个（引擎对它们没有任何策略） | 90.0% | 70.8% |

所以最终口径是：**引擎挂了 `choose` 的一律不抢**，只接管它一片空白的那五类。

### 两个顺带挖出来的缺陷

**1. 推演克隆拿真棋盘做判断。** `cloneForSim` 按引用共享 `chooser`，而 AI 装的那个
是闭包绑死真对局 state 的 —— 推演里每一问都用真实局面算，却作用在推演局面上，
规划器据此挑的牌自然是错的。现在给 chooser 加了 `aiRebind`，克隆时重新绑到克隆体自己身上。

**2. 回放录制会错位。** `takeChoice` 里 chooser 直接 return 答案那条路不经过 `hold()`，
不记流水；而回放靠「一问一条」的游标对齐。录制时 AI 答的每一问都漏一条 ——
12 局实测 **103 问只有 76 条流水**，缺 27 条，播到后面报
「有挂起的交互请求，但没法回答」。现在 `choices.js` 认 `state.chooserRecords`：
只由 `aiTakeTurn` 置（回放播放器不置，它本来就是读流水的）。修完 103/103。

### 战斗动画重做（作者 2026-10：「轻飘飘」）

全部重写 keyframe，核心是**给撞击加形变**——以前只有 ±4px 的纯平移，撞上去像被风吹了一下；
有分量的撞击必然带压扁。

| 动画 | 原来 | 现在 |
|---|---|---|
| 受击（`fx-shake`） | ±4px 平移，无压扁 | 6px + 横向缩/纵向拉，回摆反过来；时长反而压到 .30s |
| 闪白（`fx-flash`） | `brightness 2.4 / saturate .35` —— 压到 .35 几乎变灰 | `2.1 / .6`，偏高饱和才像一次真实闪光 |
| 出手（`fx-flip-*`） | 从 0 帧直接开始翻牌，没有预备动作 | 先蓄力（反向缩一点）→ 翻一圈冲出去（带速度拉伸）→ 撞完回弹过一点 |
| 落点（`fx-drop`） | 手写 `classList.add` + `setTimeout` | 统一走 `fxPulse`，时长常量化（`FX_DROP_MS`） |

手牌落槽（`fx-draw`）同样从手写定时器改成 `fxPulse`。

## 实测胜率

13 个阵营双方随机、双向座位、每档 120 局（噩梦按 +2费 / +2张牌 / +8王血）：

| 对手 | 0.74.0 | **0.75.0** |
|---|---|---|
| 简单 | 97.5% | **98.3%** |
| 普通 | 95.0% | **95.0%** |
| 困难 | 90.8% | **91.7%** |
| 噩梦(+2/+2/+8) | 71.7% | **70.8%** |

差异都在 ±1 局（1/120）以内，属于噪声范围 —— 这一版对棋力是中性的。

> **口径说明**：测试牌库 `buildTestDeck` 排除带 `faction` 的卡，阵营超能力只能靠
> 国王掉血过 15/9/3 阈值抽到，平均一局一两张。所以上表量的是「普通卡池对普通卡池」，
> 阵营机制只是陪跑。要单独量阵营强度，需要另建一套「普通卡 + 本阵营超能力」的牌库。
