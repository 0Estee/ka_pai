# 云存档与账号（0.61.0 设计稿）

目标：用户名 + 密码登录；登录后把**玩家档案 profile** 同步到 Cloudflare；
管理员账号可以查看 / 删除用户、重置密码。

范围：只同步 profile（金币、星尘、表现分、战绩、强化工坊进度）。
**回放不同步** —— 一局回放动辄几十 KB，几十局会超过单条存储上限，
而且回放是本地观看的，换设备后没有也不影响继续玩。这一点在界面上要写清楚。

## 1. 服务端 API（同源 /api）

所有响应都是 JSON；错误统一为 { ok:false, error:'code', message:'中文' }。
除注册 / 登录外，都要带 Authorization: Bearer <token>。

| 方法 | 路径 | 请求 | 成功响应 |
| --- | --- | --- | --- |
| POST | /api/auth/register | {username,password} | {ok:true, token, user:{username,role}} |
| POST | /api/auth/login | {username,password} | {ok:true, token, user:{username,role}} |
| GET | /api/auth/me | — | {ok:true,user:{username,role,createdAt,lastLoginAt}} |
| POST | /api/auth/logout | — | {ok:true}（客户端删 token 即可） |
| POST | /api/auth/password | {currentPassword,newPassword} | {ok:true,token}（旧 token 全部失效） |
| GET | /api/save | — | {ok:true,save:{data,version,updatedAt} 或 null} |
| PUT | /api/save | {data,baseVersion} | {ok:true,save:{version,updatedAt}} |
| GET | /api/admin/users | — | {ok:true,users:[...]} |
| POST | /api/admin/reset-password | {username,newPassword} | {ok:true} |
| POST | /api/admin/delete | {username} | {ok:true} |
| GET | /api/admin/save?username= | — | {ok:true,username,save:{data,version,updatedAt,bytes,summary} 或 null} |
| POST | /api/admin/save | {username,patch} **或** {username,data} | {ok:true,save:{data,version,updatedAt,bytes,summary}} |
| GET | /api/admin/log | — | {ok:true,log:[{at,by,username,fields,version,note}]}（倒序，最多 20 条） |

状态码：400 参数不合法；401 未登录 / 密码错 / token 过期；403 非管理员；
404 用户不存在；409 用户名已存在 / 存档版本冲突；413 存档过大；429 登录尝试过多。

### 1.1 存档冲突

PUT /api/save 带 baseVersion（第一次上传传 0）。服务端当前版本不等于它时返回
409 {ok:false,error:'conflict',save}，客户端让玩家选「用云端 / 用本地」。
存档 data 最大 **64 KB**（profile 正常只有几 KB）。

### 1.2 管理员

- 默认管理员：用户名 123，密码 1145145。
- 服务端首次初始化时创建；密码只存 PBKDF2 哈希，客户端永远拿不到哈希。
- 可用环境变量 ADMIN_USERNAME / ADMIN_PASSWORD 覆盖默认值；
  部署后建议 npx wrangler secret put ADMIN_PASSWORD 换掉默认密码。
- 管理员列表不能返回 hash / salt；只能返回
  {username,role,createdAt,updatedAt,lastLoginAt,save:{version,updatedAt,bytes,summary}}，
  summary 只含 {games,wins,perf,gold}。
- 管理员不能删除自己；重置密码会让该用户旧 token 失效。

### 1.2.1 管理员改玩家数据（0.69.0）

管理员可以**直接改某个玩家的云存档**，两条路要二选一：

- `patch` —— 只改白名单里的数值，其余字段原样保留。白名单与范围：

  | 字段 | 范围 | 说明 |
  |---|---|---|
  | gold | 0~1000 | 客户端 `GOLD_CAP`；超出部分会被客户端熔成星尘，所以先在服务端夹住 |
  | dust | 0~500 | 客户端 `DUST_CAP` |
  | perf | 0~10000000 | 表现分；**等级由它推算**（客户端没有独立的等级字段） |
  | lifetimeGold | 0~10000000 | 只存档兼容用 |
  | games / wins / losses / draws | 0~1000000 | 战绩 |
  | forge | `{v:1,cards:{…}}` | 强化表；形状按客户端口径清洗（lvl 0~9、精通最多 2 个、空记录丢掉） |

- `data` —— 整份替换（高级编辑）。服务端仍会过一遍 `forge` 清洗，并同样受 64 KB 限制。

落库时 **version + 1**、重算 `bytes/summary`、更新 `updatedAt`，并往
`meta:adminlog` 追加一条审计（谁、什么时候、改了谁、哪些字段、新版本号），
日志最多 50 条，`GET /api/admin/log` 倒序取最近 20 条。

语义要点：

- 管理员改的是**云端那份**。玩家设备上的本地存档不会被动——
  他下次上传会拿到 409 `conflict`，在「选择保留哪一份」里点「用云端」才会采纳。
  这样管理员的改动不会被玩家一台离线设备的旧进度静默覆盖。
- 响应里依旧不含 hash / salt；`patch` 与 `data` 同时给返回 400。
- 目标用户不存在返回 404；没有那个人的存档时以「空档案」为底写一份新的（version 1）。

### 1.3 密码与 token

- PBKDF2-SHA256，16 字节随机盐，默认 100000 次（可用 PBKDF2_ITERATIONS 降低）。
- token 是无状态 HMAC-SHA256（payload 含 u 用户名、r 角色、tv tokenVersion、exp 30 天），
  密钥优先取 AUTH_SECRET，没有就在 Durable Object 存储里生成一次并持久化。
- 所有比较用常量时间；错误信息不区分「用户不存在」和「密码错误」。
- 登录失败：同一用户名 5 次失败后锁 10 分钟（存用户记录里，成功登录清零）。

### 1.4 存储

新增 Users Durable Object（SQLite 后端，单实例 global）：

- user:<小写用户名> → {username,role,salt,hash,iterations,tokenVersion,createdAt,updatedAt,lastLoginAt,failCount,failUntil}
- save:<小写用户名> → {data,version,updatedAt,bytes,summary}
- meta:secret → 自动生成的 HMAC 密钥（base64）
- 用户名规则：2~20 个字符，只允许中文、字母、数字、下划线；大小写不敏感；
  123 是管理员保留名，注册时拒绝。

### 1.5 路由

cloudflare/src/room.js 的 default fetch 在房间路由**之前**拦截
/api/auth/*、/api/save、/api/admin/*，转给 env.USERS.idFromName('global')。
OPTIONS 预检直接 204 + CORS 头（APK 从 file:// 请求公网 API 时会用到）。

## 2. 客户端行为

- 新模块 app/js/cloud.js：
  - 登录态存 Store.loadCloudAuth / saveCloudAuth / clearCloudAuth（token 只在本机）。
  - API 地址：页面是 http(s) 时用同源 /api；file://（APK）时用
    https://wangzuo.icu/api。常量 CLOUD_BASE 放在文件顶部。
  - init({onChange})：读登录态、注册 Store.setCloudSaveHook（防抖 2s 上传）。
  - login/register：成功后先 GET /api/save：
    - 云端没有存档 → 上传本地；
    - 本地是空档（games=0 且 perf=0）→ 直接采用云端；
    - 两边都有 → 进入冲突态，**不自动覆盖**。
  - useLocal() 用当前云端版本号覆盖上传；useCloud() 把云端 data 经
    Store.normalizeProfile 写回本地并 setProfile。
  - cloudStatus() 返回：
    {user, busy, error, notice, lastVersion, lastSavedAt, conflict, admin:{users,loading,error,confirmDelete}}
  - 管理员：loadAdminUsers / deleteUser / resetPassword。
- app/js/screens.js 新增 accountHTML({cloud})、adminHTML({cloud})。
- app/screens.css 新增 .cloud-* 样式，沿用首页的台账风格（无渐变、无发光、无 emoji）。
- 首页「更多入口」加一行「云存档」，未登录写「登录 / 注册」，已登录写
  「已登录 · 用户名」；点击 data-act="open-account"。
- 设置页 / 账户页都要有一句「云存档同步金币、等级与强化进度；回放仍只保留在本机」。

## 3. 界面动作与 DOM 契约（Lead 负责接线）

### data-act

- open-account：进账户页
- cloud-login / cloud-register：读 #cloud-user、#cloud-pass
- cloud-logout
- cloud-push：立即上传本地
- cloud-pull：拉云端（有本地进度时进入冲突态）
- cloud-use-local / cloud-use-cloud：冲突二选一
- cloud-change-password：读 #cloud-oldpass、#cloud-newpass
- cloud-admin-open：进管理后台（仅管理员）
- cloud-admin-refresh
- cloud-admin-back
- cloud-admin-delete：data-user，第一次点击进入确认态
- cloud-admin-delete-confirm / cloud-admin-delete-cancel：data-user
- cloud-admin-reset：data-user，新密码读 #cloud-admin-pass
- cloud-admin-edit：data-user，展开「改数据」面板（0.69.0）
- cloud-admin-save：把面板里七个数字落进状态再 POST（读 #admin-gold / #admin-dust /
  #admin-perf / #admin-games / #admin-wins / #admin-losses / #admin-draws）
- cloud-admin-clear-forge：清空这个人的全部强化（patch.forge = 空表）
- cloud-admin-raw：展开 / 收起「整份 JSON」编辑
- cloud-admin-save-raw：读 #admin-raw 整份替换（客户端先解析 JSON，格式错就不发请求）
- cloud-admin-edit-close：收起面板
- 返回按钮沿用 back-home

### 输入框 id

cloud-user、cloud-pass、cloud-oldpass、cloud-newpass、cloud-admin-pass、
admin-gold、admin-dust、admin-perf、admin-games、admin-wins、admin-losses、
admin-draws、admin-raw。

### 屏幕

screen = 'account' | 'admin'；SCREEN_DEPTH 分别 1 / 2；
window.__go 支持这两个值。
