# 0.32.0（versionCode 33）

本次只动界面与回合循环，规则本身没有改。可以直接覆盖安装 0.31.0。

## 作者报的两个界面问题

1. **伤害提示会被遮挡** —— 伤害掉字（`-3`、`消灭`）是挂在格子里面的，而格子样式 `.slot` 带着 `overflow: hidden`，数字一飘出格子边缘就被裁掉；相邻格子的不透明背景还会盖在它上面。
   - `app/style.css`：`.slot` 的 `overflow: hidden` 改成 `overflow: visible`（格子本身不需要裁剪：单位自己带圆角与裁剪）；`.fx-float` 的 `z-index` 由 6 提到 9。
2. **锦囊的使用提示不正确** —— 放大展示的横幅把 `<small>卡面效果</small>` 当成纯文本显示，玩家看到的是字面标签。
   - `app/js/render.js`：`showBanner(text, ms, sub)` 增加第三段文本（存进 `view.bannerSub`）。
   - `app/js/ui.js`：横幅渲染时把第二段包进 `<small>` 并转义。
   - `app/js/game-flow.js`：锦囊放大展示、陷阱触发、陷阱埋伏三处改成两段式调用。

## 顺带修掉的回合循环隐患（真机上表现为偶发卡住）

- `app/js/game-flow.js`：AI 分支与玩家阶段兜底的那两次 `advanceGame()` 没有判断 `state.pending`，开战挂起等人点目标时照推，引擎抛 `存在待处理的交互请求，无法推进`；这个异常发生在定时器里，被吞掉，结果是这一次推进凭空丢失。两处都补上 `!state.pending` 守卫。
- `app/js/game-flow.js`：`newGame()` 只清了横幅与玩家兜底的定时器，没清自动阶段与 AI 阶段的定时器（那些回调捕获的是旧的一局），也没有复位 `autoAdvancing`（一旦停在 true，自动阶段就永久停摆）。现在新增 `autoPhaseTimer` / `aiTurnTimer` / `aiAdvanceTimer` 三个句柄，开局时一并取消并复位。

## 门禁

- 新增 `tools/checks/22-spell-banner.mjs`（3 条）：锦囊横幅必须是卡名加效果两行、源码里不许再把 HTML 标签塞进横幅文本、`.slot` 不许裁剪掉字且 `.fx-float` 必须有层级。
- 修门禁自身的坑：ESM 的顶层 `await` 不会串行化同一批静态依赖。`tools/check-bundle.mjs` 里排在后面的分组会和前面分组的 `await` 并发执行，`22-spell-banner` 建局用的 `__newGame()` 会在 `20-combat-suspend` 场景跑到一半时把共享的 `state` 换掉，于是 20 号报「开战挂起没有出现」。现在 20 号：开工前清空共享的定时器桩，并在检测到 state 被换掉时重跑场景（对方只在它自己的模块体里换一次）。
- `node tools/check-bundle.mjs`：全部通过。
- `node engine/test/smoke.mjs`：86 个规则回归测试全部通过。
